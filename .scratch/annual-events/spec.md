# Annual events

Status: Implemented

Vocabulary is defined in `CONTEXT.md` (Annual event, Annual event window, Annual event item). Decision record: [ADR 0040](../../docs/adr/0040-annual-events-judged-on-the-device-calendar.md).

## Confirmed decisions

- An Annual event is a yearly occasion tied to a calendar date. Eight of them: Halloween, Winter holidays, Easter, Midsummer, Spring, Summer, Autumn, Winter.
- Anchor dates, northern hemisphere: Halloween 31 October; Winter holidays 25 December; Easter the Western (Gregorian) Easter Sunday, computed each year; Midsummer the Friday between 19 and 25 June; Spring 20 March, Summer 21 June, Autumn 22 September, Winter 21 December.
- Window: from 21 days before the anchor date to 14 days after it, both days included, judged on the local date of the player's device. A Time skip never changes it. Windows may overlap, so several Annual events can be active together. A window can span the new year.
- Annual event items: Buildings sold from 700 to 1500 Urbs, no Citizens threshold, no Build limit, no Escalating price, no effect and no upkeep. They are never Retired. Once placed they stay for good: they work, move and demolish like any building. Only a new placement outside every window of their event is refused, with a fixed error message (`error.annualEventClosed`); the dates are shown in the Codex page of the item.
- Build menu: a new section "Annual events" (FR "Évènements annuels"), between Agriculture and Decoration. Hidden while no window is open. When shown, items are grouped by Annual event, in the order of `assets/defs/order/buildings.json`.
- Notice: a dismissable banner while a window is open, once the Tutorial is done and never in read-only mode. It names the event, says until when its items can be built, and opens the section. Dismissal is stored in the browser per event and per year (year of the anchor date), outside the save and the Cloud save. One notice at a time: the next event's notice shows once the previous one is dismissed. "See" opens the section and dismisses the notice.
- Codex: always lists Annual event items, with the anchor date of their event; the build menu stays hidden outside the window. Codex images are regenerated.
- Data: one file per event in `assets/defs/annualEvents/<id>.json` (names FR/EN and an anchor rule: `fixed`, `easter` or `weekdayInRange`), validated by a generated schema. The window rule is a pure function `annualEventWindow(event, year)` in the core; `placeBuilding` receives `now` like any command. Each item declares `annualEvent: "<id>"` in its `standard` definition, with `section: "build.annualEvents"`. No assets-editor UI in this delivery.
- Scope of the first delivery: the whole mechanism for the eight events, and the Halloween catalogue only. An event with no item has no section entry and no notice.
